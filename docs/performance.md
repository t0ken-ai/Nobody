# 常驻性能检查（2026-09-27）

本轮范围经用户确认：减少空闲取词、隐藏页面刷新、记录复制和过期缓存；检查 Windows 空闲轮询。保留现有翻译、浮窗和后台收发功能。

## 运行方式

- 350 ms 选区检查先看手势元数据。没有新手势、待稳定选区或需跟随的结果时，不读取焦点控件、正文或选区几何。700 ms 稳定等待和原控件跟随保持原有频率。
- macOS 对新遇到的白名单应用预先请求一次 `AXManualAccessibility`，兼容 Electron 延迟建立辅助功能树。自动阅读不再取整个 `AXValue`；完整值只服务于明确的整框翻译和安全回填。
- 关闭自动划词后，原生鼠标监听停止；无需跟随手动结果时也停止桥接调用。Windows COM 线程改为等待任务或快照过期，避免禁用状态仍每 16 ms 唤醒。
- Windows 请求队列上限 16；超时调用在出队时丢弃，避免不响应的第三方 UIA 服务积累无限请求。操作已开始后仍受第三方服务响应能力限制。
- 主窗口隐藏或互传页不可见时，不请求记录快照或重绘；演示停止动画帧。后台服务继续工作，首次信任事件明确唤醒主窗口。返回时更新状态，保留草稿和未保存设置。
- 不变的设备、记录节点保持原位；mDNS 周期验证只有实际变化才通知界面。
- 历史预览直接截取 180 个 Unicode 字符，避免先复制完整正文。关闭全文对话框释放额外 DOM 文本。图标缓存上限跟随 100 个草稿应用，并通过一个定时器清理 5 分钟过期项。
- 回填快照最多保留 120 秒，过期后即释放原文和原生对象，无需等待下一次翻译。macOS 主窗口关闭 5 秒后，对仍然隐藏的窗口执行一次系统分配器闲置页回收；不强制换出活动内存。

## 验证

- Rust：49 项通过；另显式运行本机真实 mDNS 发现测试，双向发现通过。TLS 测试使用临时身份和独立目录，未修改用户信任或收件数据。
- 原生 macOS 纯判断函数：10 个案例，覆盖无手势、旧手势、过期、按住、稳定等待、来源跟随及手动调用。
- 浏览器使用生产前端和本地模拟 IPC：16 个性能案例、16 个互传分页案例、11 个图标案例、35 个平台快捷键及演示案例通过。模拟 IPC 不等于 Windows 原生应用验收。
- 隐藏窗口下 100 次进度事件产生 0 次记录快照请求；可见页面同一批事件合并为 1 次。验证了隐藏期间返回的异步结果不重绘、重新打开后补齐、配对唤醒、草稿保留和动画暂停/恢复。
- macOS 最终包编译及签名校验通过。Windows 原生适配模块通过 `x86_64-pc-windows-gnu` 的编译检查，尚未做 Windows 整应用或真机 CPU/内存验收。
- 最终包完成系统钥匙串认证后正常启动，界面显示“跨应用翻译已就绪”。用户将互传页切到前台后确认设备和记录正常显示；原生界面复核为 1 台在线设备、9 条历史记录。后台自动化点击时页面暂停刷新，前台恢复后补齐，未丢失服务状态。

## 采样口径与结果

同一台 Apple Silicon Mac，macOS 27.0，debug 应用包。`top` 每 2 秒采样，去掉首个非区间样本。机器同时运行大量其他进程、存在压缩内存，短时间数值只能用于本机观察，不能作为跨机器性能保证。

第一轮优化（尚未增加关闭窗口后的分配器回收）的后台主进程 CPU：旧版 5 个区间均值 1.04%，新版 10 个区间均值 0.58%。旧版采样出现 `focused / AXUIElementCopyAttributeValue`；新版空闲采样未出现该读取路径。

内存使用 `Physical footprint` / `top MEM`，不是虚拟地址空间，也不把单一主进程称为整个应用占用。旧版主进程约 37 MiB，四个 WebKit 工作进程合计约 147 MiB；它们与应用的关系通过 Activity Monitor 应用筛选确认。第一轮新版主进程曾从启动后的约 114 MiB 回落到约 63 MiB；分配器报告约 15 MiB 活跃分配，另有已空闲但未归还的页，不能据此声称存在泄漏或内存已经下降。

最终构建在认证结束、互传服务和界面均确认就绪后，关闭主窗口再次采样。10 个区间的后台主进程 CPU 为 0.3%–0.9%，均值 0.59%；四个 WebKit 工作进程在这些区间均为 0.0%。主进程约 43 MiB，主页面 WebContent 93 MiB、结果 WebContent 23 MiB、GPU 21 MiB、Networking 6.7 MiB，合计约 187 MiB。`vmmap` 的主进程 Physical footprint 为 42.7 MiB，空闲调用栈未出现 AX 正文读取或钥匙串等待。

本次短测支持空闲 CPU 降低的结论；整应用内存与旧版约 184 MiB 接近，不能声称内存占用已经下降。延迟回收只请求归还分配器闲置页，无法据不同启动的数值单独归因；主要内存改进是限制积压和缓存生命周期。真实 Codex 前台划词和快捷键回填已请用户复测，尚未收到本轮结果。
