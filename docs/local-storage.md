# 本地存储与备份

[返回 README](../README.md)

## 数据位置

macOS 与 Windows 使用相同的用户目录布局，`~` 表示当前用户主目录。应用不使用 macOS Keychain 或 Windows Credential Manager。

| 路径（相对 `~/.translateme/`） | 内容 |
| --- | --- |
| `llm/llm.db` | SQLCipher 数据库：按接口隔离的 API Key 与最后保存的 LLM 配置 |
| `llm/master.key` | 随机 256 位数据库解密密钥 |
| `transfer/device/identity.json` | 本机局域网 TLS 证书与私钥 |
| `transfer/device/trusted.json` | 当前设备身份确认过的受信任设备 |
| `transfer/settings.json` | 设备名称、互传开关和接收目录等设置 |
| `transfer/inbox.json` | 有界的发送／接收记录，包含收到或发出的文字 |
| `received/` | 默认接收文件目录，可由用户修改 |

非密钥偏好设置还保存在 Tauri 的应用配置目录，作为快捷键、目标语言、白名单和引擎配置的兼容副本。翻译历史不保存；发送的源文件不会复制到上述目录。

## 保护边界

数据库和解密密钥存放在同一目录，**获得完整 `llm/` 目录即可解密 API Key**。这提供本地文件加密，不等同于独立的系统凭据保险库。macOS 私密目录／文件使用 `0700`／`0600` 权限，Windows 使用当前用户的受保护 ACL；管理员和同账户程序仍可能取得这些文件。

互传记录 JSON、设备身份文件和接收文件不因位于 `.translateme/` 下而获得 SQLCipher 加密。TLS 保护传输过程，不代表接收文件在磁盘上加密。

新私密文件先写入受保护的临时文件再原子发布。密钥缺失、损坏或不匹配时保留原文件并返回错误，不静默重置数据库或设备身份。

## 备份与恢复

- 重装应用时保留整个 `llm/` 目录即可恢复 LLM 配置和密钥；只有 `llm.db` 无法解锁。
- 恢复同一设备的互传身份时保留整个 `transfer/device/`。不要让多台在线电脑共用同一份设备私钥；各台电脑应自行生成身份并配对。
- 需要完整恢复记录和互传设置时保留整个 `transfer/`；接收文件另行备份，自选接收目录也需单独保留。
- 替换数据前退出应用，备份视为敏感文件保管，不提交到 Git，也不随安装包分发。

清除传输记录不删除接收文件。解除信任会撤销该设备的后续自动接收资格，并取消其当前任务。

## 旧版 TranslateMe 数据

Nobody 保留 Bundle ID 和 `.translateme/` 路径以支持升级。旧 `llm.db` 与 `transfer/trusted.json` 原位保留作备份；当前版本不解锁旧数据库、不读取旧系统凭据，也不沿用旧信任。升级到本地密钥方案后，需要重新填写 API Key 并重新配对；非密钥设置、历史记录和已接收文件可保留。

早期位于应用配置目录的互传元数据会先校验、复制，再切换到 `.translateme/transfer/`。已有新目录为准，不被旧副本覆盖；旧文件和历史记录中的文件路径不搬动。旧默认接收目录改为新默认值，用户自选目录保持不变。
