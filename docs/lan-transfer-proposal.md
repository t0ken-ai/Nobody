# 局域网互传方案

状态：用户已确认以下架构；macOS 实现已接入，详细验收结果见 `verification.md`。两台实体 Mac 与 Windows 实机结果分别记录，不以本机双实例替代。

## 已确认的体验

- 在 TranslateMe 中发现同一局域网里已安装、正在运行且可互相访问的电脑，按设备名称和系统选择发送对象，支持 macOS / Windows。
- 发送文字、单个文件和多个文件。文件夹不在范围内。
- 首次确认信任，之后自动接收并通知。最新决定替代此前“先接收、打开时确认”的讨论：陌生设备先完成信任确认，再传正文和文件内容。
- 文字显示在收件箱，可一键复制；文件保存到接收目录，可定位到文件。复制和打开由用户主动操作。
- 可以拒绝陌生设备的请求、取消传输、移除已信任设备。移除后，后续传输重新要求确认。

## 已确认的接入方式

保留现有 Tauri + Rust + TypeScript 技术栈，在同一个应用中增加独立的局域网互传模块。

| 位置 | 职责与边界 |
| --- | --- |
| `src-tauri/src/transfer/` | 持有独立状态，管理发现、身份、信任、传输任务与收件箱；网络核心不调用翻译引擎或读取选区。 |
| `transfer/discovery.rs` | 发布和浏览局域网服务，处理在线、离线及地址变化；发现信息只用于定位候选设备，不能授予信任。 |
| `transfer/identity.rs`、`store.rs` | 管理本机稳定身份、已信任公钥及本地接收记录。设备名称、IP 变化不改变信任；密钥变化需重新配对。 |
| `transfer/transport.rs`、`protocol.rs` | 加密连接、首次配对状态、流式收发、进度、取消、完整性确认；协议带版本号。 |
| `transfer/commands.rs` | Tauri 命令与 UI 事件适配；仅主窗口可管理设备、选文件和发起传输，译文浮窗没有这些权限。 |
| `src/transfer.ts`、独立样式文件 | 设备列表、发送区、收件箱和信任确认 UI，适配系统深浅外观。 |
| 现有 `main.rs` / `main.ts` | 注册服务生命周期、命令和页面入口；传输使用自己的任务队列，不占用翻译的单请求锁。 |

主界面新增“局域网互传”导航：左侧选择设备，右侧输入文字或添加文件，下方显示发送／接收记录。关闭主窗口后继续驻留接收；退出应用时停止广播和监听。提供互传开关。

涉及独立模块、入口注册、依赖、macOS 用途说明、样式与文档；用户按本聊天协作准则 §1／§2 确认后开始实现。现有翻译设置、引擎和选区模块不依赖互传服务。

## 发现与首次信任

1. 每台电脑在本地生成独立设备密钥；对外显示可修改的设备名称和操作系统。
2. 使用 mDNS/DNS-SD 发布并发现 `_translateme._tcp.local.` 服务，随后直接连接目标电脑。广播只包含定位所需的设备元数据，文字、文件名及内容不广播。
3. 用户选择设备并发送后，首次连接进入配对流程。双方显示与本次连接及设备身份绑定的校验码，核对后确认信任，形成双向配对。
4. 配对完成后持久化对方身份，才发送本次内容。拒绝或超时则结束，发送端得到明确结果。
5. 已配对连接验证保存的身份后自动接收；同名设备或复用旧 IP 的设备不能继承信任。撤销信任同时取消该设备仍在进行的传输。

设备必须在线且网络允许互通。跨网段、访客网络隔离或组播被阻止时，不能承诺发现所有已安装电脑；界面应区分“暂无在线设备”和可诊断的发现／监听错误。

## 传输与本地存储

- **传输**：设备之间使用 TLS 加密直传，不需要云端账号或中转。配对与业务数据严格分阶段；未信任连接只允许有限的配对消息。
- **文件**：通过原生文件选择器或拖入添加，由后端校验为普通文件并流式读取，避免将整个文件编码到前端内存。
- **完成判定**：接收方写临时文件并检查长度及摘要，成功落盘后返回确认；发送方收到确认才显示“已完成”。取消、断连、磁盘不足显示明确状态并清理未完成文件。
- **接收目录**：默认使用本机 Downloads 下的 `TranslateMe` 目录，可修改；同名文件生成新名称。接收方决定落盘路径，发送方不能指定任意本机路径。
- **设备私钥**：按后续确认的无系统凭据库方案，保存在 `~/.translateme/transfer/device/identity.json`，只供当前账户访问；独立于 LLM 数据库。旧系统身份不读取、不导入；新身份重新配对，旧信任文件原位保留。
- **互传设置与信任**：应用配置目录新增 `transfer/settings.json` 和信任记录，保存设备名称、开关、接收目录及受信任身份；原翻译设置不承载这些字段。
- **收件箱**：本地保存有界的近期文字与文件记录，支持清除。清除接收记录与删除已保存文件是独立操作。译文仍遵循现有“不保存翻译历史”的规则。
- **通知**：收到内容时更新应用收件箱和托盘提示；系统通知获准时同时通知，拒绝系统通知权限仍可正常接收和查看。

## 依赖方向与依据

- 用 [`mdns-sd`](https://docs.rs/mdns-sd/latest/mdns_sd/) 进行服务发布、浏览与离线事件处理；其文档明确提供注册／浏览接口与异步事件接收。
- 用 [`rustls`](https://docs.rs/rustls/latest/rustls/) / `tokio-rustls` 建立设备间的 TLS 连接。这两项及 SHA-256 实现已存在于项目锁文件的依赖树中；实现时声明所需直接依赖并锁定版本，设备证书生成另选配套库。
- 文件选择及通知优先采用 [Tauri 官方 Dialog](https://v2.tauri.app/plugin/dialog/) 和 [Notification](https://v2.tauri.app/plugin/notification/) 插件，由后端适配层调用。原文复制复用现有的显式复制命令。
- 按平台需要补充局域网用途声明与通知配置；实际系统授权由用户在相应提示中完成。

## 实施与验收顺序

1. 先完成可独立运行测试的发现、身份／信任和传输核心，验证两实例之间首次配对、已信任收发和拒绝。
2. 接入主界面、文件选择、收件箱、通知及设备管理，验证深浅外观和关闭窗口后的接收行为。
3. 测试中文与多行文字、空文件、多文件、同名文件、取消、断线、磁盘写入失败、撤销信任、伪装设备、非法文件名及路径穿越。
4. 回归现有翻译快捷键、自动划词与浮窗，确保传大文件期间翻译仍能响应。
5. 最后用真实的两台电脑验证 macOS ↔ macOS / Windows 的发现、信任及双向传输。本机两实例和交叉编译结果分别记录，不能代替多机实测。

已确认并落地的架构：独立互传模块 + 主界面入口；本机稳定设备身份和信任存储；mDNS 发现 + TLS 1.3 直传；独立收件箱与文件接收目录。

第一版网络范围为 IPv4 私有／链路本地地址，回环仅用于诊断，不广播公网或 IPv6 地址。文字最多 1 MiB、100 个文件、单文件 20 GiB、单次 40 GiB；文件以 64 KiB 分块收发。记录保留最近 100 条、总文字最多 8 MiB。系统通知可能受系统通知设置限制，收件箱接收独立于通知。
